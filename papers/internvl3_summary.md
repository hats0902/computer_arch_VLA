# InternVL3 論文メモ

**InternVL3: Exploring Advanced Training and Test-Time Recipes for Open-Source Multimodal Models**
（ReCogDriveのベースVLMとして使われている関連論文）

## 背景にあった課題

- 画像も扱えるLLM（MLLM）は、多くのタスクで人間並みの性能に達するほど進歩している。
- ただし主要なMLLMの多くは、まず文章だけでLLMを完成させ、後から画像を扱えるように何段階も追加学習する「後付け（post-hoc）」の方式で作られている。
- 文章だけで学んだモデルに後から画像を教えるので、画像と言葉の対応づけ（アライメント）がうまくいきにくい。
- そのため、文字認識（OCR）のような専門データを足したり、言語能力を壊さないよう一部の重みを固定して段階的に学習したりと、手間とコストのかかる工夫が必要だった。
- **このギャップを埋めるために**：文章と画像を最初から一緒に学ぶ、より効率的な学習方法が求められていた。

## 提案していること

- **ネイティブなマルチモーダル事前学習**：テキスト専用LLMを後から改造するのではなく、マルチモーダルデータと純粋なテキストコーパスを使い、1回の事前学習で視覚と言語の能力を同時に身につける。
- **V2PE（可変視覚位置エンコーディング）**：長いマルチモーダルの文脈（大量の画像トークンを含む入力）を扱えるようにする。
- **事後学習**：SFTとMPO（混合選好最適化）で性能をさらに高める。
- **テスト時スケーリングと学習基盤**：推論時に計算を増やして精度を上げる戦略と、最適化した学習インフラを採用する。
- **結果**：InternVL3-78BがMMMUで72.2を記録し、オープンソースMLLMでSOTA。GPT-4o、Claude 3.5 Sonnet、Gemini 2.5 Proなどの商用モデルとも競える性能で、テキストのみのタスクでも高い能力を保つ。
- **公開**：学習データとモデルの重みを公開予定。

## アーキテクチャ

**全体構成：ViT-MLP-LLM**（前のバージョンと同じ枠組み）

```
画像 ──▶ タイル分割(448×448) ──▶ InternViT ──▶ pixel unshuffle ──▶ MLP ──▶ ┐
                                  (1024トークン/タイル)  (256トークン/タイル)      ├─▶ LLM（V2PEで位置付け）──▶ 出力
テキスト ──────────────────────────────────────────────────────▶ 埋め込み ──▶ ┘
```

| 部品 | 中身 | 初期化 |
|---|---|---|
| Vision（ViT） | InternViT-300M または InternViT-6B | 学習済みの重み |
| つなぎ（MLP） | 2層のMLP。画像特徴をLLMの次元に変換する | ランダム初期化 |
| LLM | Qwen2.5シリーズ または InternLM3-8B | 学習済みの**ベースモデル**（指示チューニング版は使わない） |

- **スクラッチではない**：ネイティブ事前学習ならスクラッチ学習も可能だが、計算コストを抑えるためViTとLLMは学習済みの重みから始める。

### 通常のViTからの追加・変更点

| 機構 | 場所 | 何をするか | 狙い |
|---|---|---|---|
| タイル分割（動的解像度）※補足 | ViTの前 | 高解像度の画像を448×448のタイルに分けて、タイルごとにViTに通す | 解像度の高い画像を細部まで扱う |
| pixel unshuffle | ViTとMLPの間 | 隣り合う2×2のトークンを1つにまとめ、トークン数を1/4にする。1タイル＝256トークン | LLMに入る画像トークンを減らし、高解像度でも計算が膨らまないようにする |
| V2PE | LLMの位置エンコーディング | テキストは位置を1ずつ、画像トークンは1より小さいδずつ進める | 画像トークンが大量でも位置の範囲（コンテキスト長）を使い切らない |

- **InternViT自体**：構造は通常のViTとほぼ同じで、違いは主に規模（最大6B）と学習のさせ方（重み）。詳細は下の「InternViTの詳細」を参照。
- **pixel unshuffleの計算例**：パッチサイズ14なら、448÷14＝32で32×32＝1024トークン → 2×2をまとめて16×16＝256トークン（チャネル数は4倍）。※パッチサイズ14は補足。
- **V2PEの計算例**：δ＝1/16なら、256個の画像トークンは位置を16しか消費しない（通常なら256）。
- **V2PEのδの決め方**：1枚の画像内ではδは一定。学習時は {1, 1/2, …, 1/256} からランダムに選び、推論時は入力の長さに応じて選ぶ。δ＝1なら従来（InternVL2.5）と同じ。

### InternViTの詳細（出典：InternVL論文 3.1, 3.2。[1]）

- **構造**：普通のViT（vanilla ViT）そのもので、構造上の特別な工夫はない。
- **規模**：組み合わせるLLMと釣り合うよう60億パラメータ（InternViT-6B）まで大きくした（当時の一般的なCLIP ViT-Lは約3億）。
- **構成の決め方**：深さ{32, 48, 64, 80}、ヘッド次元{64, 128}、MLP比{4, 8}を探索し、幅とヘッド数はパラメータ数から決めた。最終構成はTable 1（補足：48層・幅3200・25ヘッド・MLP比4と記憶、要確認）。
- **探索の結果（速度）**：GPUの計算を使い切っていないときは浅いモデルほど速いが、使い切ると差はほぼなくなる。
- **探索の結果（精度）**：パラメータ数が同じなら、深さ・ヘッド次元・MLP比は性能にほとんど影響しない。
- **学習方法**：大量のノイズを含むデータでの対照学習から始め、高品質データでの生成学習へ段階的に移る「段階的アライメント学習」でLLM側と整合させる。
- **300M版**：InternVL3にある300M版は、後のバージョンで6B版から蒸留した小型版（補足、要確認）。ReCogDriveの2B版・8B版も300M版を使っていると思われる。
- **高速化への示唆**：自動運転の推論はバッチサイズ1に近く、GPUの計算を使い切らないので、パラメータ数が同じでも層の深さがレイテンシに効きやすい。

## 用語集

| 用語 | 説明 |
|---|---|
| InternVL3（本論文の提案） | InternVLシリーズの最新版のオープンソースMLLM。ネイティブなマルチモーダル事前学習で作られている。 |
| MLLM（Multimodal LLM） | 画像などテキスト以外の入力も扱えるLLM。VLMとほぼ同じ意味で使われる。 |
| 後付け（post-hoc）学習 | テキスト専用に学習済みのLLMに、後から画像エンコーダをつないで追加学習する従来の作り方。 |
| ネイティブなマルチモーダル事前学習（本論文の提案） | 事前学習の段階から画像とテキストを混ぜて学習し、両方の能力を同時に身につける方式。 |
| アライメント（視覚と言語の） | 画像の特徴と言語の表現を、LLMが同じ意味として扱えるように対応づけること。 |
| V2PE（Variable Visual Position Encoding） | 画像トークンに割り当てる位置の刻み幅を可変にし、長いマルチモーダル文脈を扱いやすくする位置エンコーディング。 |
| ViT-MLP-LLM | 画像エンコーダ（ViT）→ 変換層（MLP）→ 言語モデル（LLM）の順につなぐ、MLLMの代表的な構成。 |
| InternViT | InternVLシリーズ用の画像エンコーダ。構造は通常のViTとほぼ同じで、300Mと6Bの2サイズがある。 |
| 対照学習（Contrastive Learning） | 対応する画像と文章の特徴を近づけ、対応しないものを遠ざける学習。CLIPが代表例。 |
| 段階的アライメント学習（InternVLの提案） | ノイズの多い大規模データでの対照学習から、高品質データでの生成学習へと段階的に移り、画像エンコーダとLLM側を整合させる学習方法。 |
| MLP比 | Transformerの各層にあるMLP（FFN）の中間層の幅が、モデルの幅の何倍かを表す値。 |
| ベースモデル | 事前学習だけを終えたLLM。指示に従うよう追加学習した「指示チューニング版（Instruct版）」と区別される。 |
| pixel unshuffle | 隣り合うトークン（2×2）をチャネル方向にまとめ、空間方向のトークン数を減らす操作。 |
| 位置エンコーディング | 各トークンが系列の何番目かをモデルに伝える仕組み。 |
| SFT（教師ありファインチューニング） | 質問と模範回答のペアで、模範回答を再現するよう学習すること。 |
| MPO（Mixed Preference Optimization） | 好ましい回答と好ましくない回答の比較などを組み合わせて学習する、選好最適化の手法。 |
| テスト時スケーリング | 推論時に計算を増やして精度を上げる戦略（複数の回答を生成して良いものを選ぶなど）。 |
| MMMU | 大学レベルの専門知識と推論を、画像付きの問題で問うマルチモーダルのベンチマーク。 |
