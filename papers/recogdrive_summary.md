# ReCogDrive 論文メモ

**ReCogDrive: A Reinforced Cognitive Framework for End-to-End Autonomous Driving**
（華中科技大学 / Xiaomi EV）
Code: https://github.com/xiaomi-research/recogdrive

## 背景にあった課題

- VLMの世界知識や認知能力を使って、自動運転のロングテール問題（まれな状況）に対応しようとする研究が増えている。
- 既存手法は、VLMが指示や粗い軌道を出して別のEnd-to-Endモデルを導く「デュアルシステム型」と、VLM単体で軌道まで出す「シングルシステム型」に分かれる。
- しかし多くは軌道を文字列として自己回帰で生成するため、フォーマット違反・実行不能な行動・推論の遅さといった問題が起きやすい（主にシングルシステム型への批判）。

| | 課題 | ReCogDriveの解決策 |
|---|---|---|
| ① | **ドメインギャップ**：VLMはネットの汎用データで学習されており、運転特有の知識が足りない | **階層的データパイプライン**で運転向けの大規模VQAデータを作り、運転認知をVLMに学ばせる |
| ② | **モダリティ不一致**：離散的な言語で連続的な軌道を出すため、実行不能な軌道やパースエラーが起きる | **拡散プランナー**でVLMの潜在表現を連続的で安定した軌道に変換する |
| ③ | **模倣学習の限界**：人間の運転を真似るだけでは、まれな場面に弱く安全性に欠ける | **DiffGRPO（強化学習）**でお手本データの外側まで探索し、より安全な行動を学ばせる |

## 提案していること

- **全体像**：自己回帰モデル（VLM）と拡散プランナーを統合し、運転の「理解」と「計画」を1つのフレームワークにまとめた。
- **階層的データパイプライン**：生成→洗練→品質管理の3段階で、人間ドライバーの順序立った認知プロセスを模したデータを作り、VLMに運転の認知を学習させる。
- **拡散プランナーへの事前知識注入**：VLMが学んだ運転の事前知識を拡散プランナーに渡すことで、言語と行動のミスマッチを解消し、連続的で安定した軌道を効率よく生成する。
- **DiffGRPOによる強化学習**：プランナーを強化学習で追加学習し、衝突を減らして安全性と快適性を高める。
- **結果**：NAVSIMとBench2DriveでSOTAを達成し、DriveBenchなどで場面理解の能力も示した。

## モデルの入出力（Problem Definition）

> 記号と軌道のshape (N, 3) は論文の記載。具体例・shape・「例」とある値は、NAVSIMでの一般的な設定などをもとにした補足で、ReCogDriveの実際の設定は実験・実装の章で要確認。

### 入力

| 記号 | 中身 | 例 | shape（例） |
|---|---|---|---|
| I_cam | 複数視点のカメラ画像（4.2に記載）。VLMに入力 | 前方・側方などのRGB画像 | (カメラ枚数, 3, H, W) |
| L_nav | ナビゲーション情報（どちらへ進むか）。テキストの質問としてVLMに入力 | 「左折」「直進」「右折」などの運転コマンド | テキスト（例：`"Command: turn left"`）→ トークン列 |
| S_ego | 自車の状態。拡散プランナーにAdaLNで入力 | 速度・加速度（論文に記載） | 速度(vx, vy)＋加速度(ax, ay)なら (4,) |
| x_hist | 過去の軌道（4.2に記載）。拡散プランナーに入力 | 過去数ステップの (x, y, heading) | (過去ステップ数, 3) |

### 出力

| 記号 | 中身 | 例 | shape（例） |
|---|---|---|---|
| V_traj | 拡散プランナーが出力する将来の経由点と向きの列（連続値。文字列を経由しない） | 各時刻の (x, y, heading)。例：`[[1.2, 0.0, 0.01], [2.5, 0.1, 0.02], ...]` | (N, 3)。4秒先を0.5秒刻みならN=8 で (8, 3) |

### 拡散プランナー内部の量（式3, 4）

| 記号 | 中身 | shape（例） |
|---|---|---|
| x_0 | ノイズのないきれいな軌道（＝V_traj） | (N, 3) |
| x_t | ステップtでノイズを加えた軌道 | (N, 3)。x_0と同じ（4.2に記載） |
| x_T | 推論開始時の純粋なノイズ。N(0, I)からサンプル | (N, 3) |
| t | 拡散ステップ番号（1〜T） | スカラー |
| ε_θ(x_t, t) | モデルが予測するノイズ。ReCogDriveではVLMの隠れ状態なども条件として入る（4.2参照） | (N, 3) |

- **学習**：x_0にノイズを段階的に足し（式3）、加えたノイズをε_θに当てさせる。
- **推論**：ノイズx_Tから始め、ε_θで予測したノイズを引く処理を繰り返して軌道x_0を得る（式4）。
- **注意**：問題定義では軌道の長さにも「T」が使われているが、拡散ステップ数のTとは別物。4.2では軌道の長さは「N」と書かれているので、このメモではNに統一。

## 4. 手法

ReCogDriveは次の3段階で構成・学習される。

1. **階層的データパイプライン（4.1）**：知覚から推論までの多段階な認知データセットを作り、VLMに人間らしい運転の事前知識を学ばせる。
2. **認知誘導型の拡散プランナー（4.2）**：VLMの潜在表現を連続的で安定した軌道に変換し、モダリティ不一致を解消する。
3. **方策の改善（DiffGRPO、4.3）**：シミュレーションで得た報酬でプランナーを強化学習し、エキスパートデータを超えて安全性・快適性を高める。

### 4.1 運転向け事前学習のための階層的データパイプライン

- **目的**：汎用VLMと自動運転の間のギャップを埋めるため、高品質な運転データを自動生成する、スケーラブルで構造化されたパイプライン（Fig. 2）。
- **構成**：Generation（生成）→ Refinement（洗練）→ Quality Control（品質管理）の3段階。
- **使い方**：作ったデータで、事前学習済みの汎用VLMを運転向けに追加学習する（スクラッチ学習ではない）。ベースのVLMは**InternVL3**（4.2に記載）。

**① Generation（生成）**：人間ドライバーの認知の順序に合わせ、4つのレベルのVQAデータを作る。客観的なタスクは正解データ（ground truth）から、主観的なタスクは最先端VLMで注釈を付けて作る。

| レベル | 内容 | 質問の例（補足） |
|---|---|---|
| (1) 基礎的な知覚 | 静的・動的なシーン要素を把握する | 「前方に何台の車がいるか？」「信号の色は？」 |
| (2) 動的な理解 | 周囲の複数エージェントの動きを分析し、直近の行動を予測する | 「右前の歩行者はこの後どう動くか？」 |
| (3) 計画と推論 | 実行可能で安全を考慮した運転計画を立て、簡潔な理由を述べる | 「次にどう運転すべきか、その理由は？」 |
| (4) 高度な推論 | 反実仮想の分析や、細かいトレードオフの評価を行う | 「もし前の車が急ブレーキをかけたらどうするか？」 |

**② Refinement（洗練）**：オープンソースのデータセットも統合し、正規化・書き換え・質問テンプレートによる水増しで、言葉づかいと意味の一貫性をそろえる。

**③ Quality Control（品質管理）**：言語的な正確さや画像の鮮明さなどで自動スコアリングし、厳しくフィルタリングして高品質なサンプルだけを残す。

- **効果**：信頼性とスケーラビリティを両立した事前学習データにより、汎用VLMを自動運転に特化した認知モデルに適応させる。

### 4.2 認知誘導型の拡散プランナー

- **狙い**：テキストで軌道を出す方式の問題（言語と行動の不一致による不自然な軌道、VLMの幻覚やデコード誤り）を避けるため、VLMの運転知識を拡散プランナーに渡して滑らかで安全な軌道を生成する。

**データの流れ（式5）**

```
複数視点画像 + テキストの質問 ──▶ InternVL3 ──▶ F_h (L, D)  ──┬──▶ 平均プーリング ──▶ F̄_h (D,)
                                                              │
ノイズ入り軌道 x_t (N, 3) ──▶ E_act ──┐                        │
過去の軌道 x_hist        ──▶ E_his ──┼── concat ──▶ z_t ──▶ DiT ──▶ D_act ──▶ x_{t-1} (N, 3)
F̄_h                      ───────────┘                ▲    ▲
                                       F_h（cross-attention）  S_ego, t（AdaLN）
```

| 記号 | 中身 | shape |
|---|---|---|
| F_h | VLMの隠れ状態。運転の事前知識を持つ「認知トークン」 | (L, D)。L：トークン数、D：隠れ次元 |
| F̄_h | F_hをトークン方向に平均プーリングした全体の意味ベクトル | (D,)（補足：shapeは平均から導出） |
| E_act / E_his | ノイズ入り軌道 / 過去の軌道を埋め込むエンコーダ | 出力shapeは記載なし |
| z_t | ノイズ入り軌道・過去の軌道・F̄_hの埋め込みを連結したもの | 記載なし |
| D_act | DiTの出力を軌道に戻すデコーダ | 出力 (N, 3) |

- **VLM（InternVL3）**：複数視点の画像とテキストの質問を隠れ状態F_hに変換し、拡散プランナーにcross-attentionの条件として渡す。必要に応じて、運転指示やChain-of-Thoughtの推論も出力できる。
- **DiTの設計**：各ブロックで、self-attention（経由点どうしの関係）とcross-attention（F_hの知識を軌道に注入）を交互に行う。安定化のためSwiGLU FFN、RoPE、QK-Norm、RMSNormを採用。
- **過去と自車の情報**：過去の軌道は埋め込んでz_tに連結し、時間的な一貫性を保つ。自車状態S_egoはAdaLNで注入し、車両の物理状態を反映させる。
- **学習（式6）**：条件 c = {F_h, S_ego} のもとで、加えたノイズεとモデルの予測ノイズの二乗誤差を最小化する。

### 4.3 DiffGRPO（拡散プランナー向けの強化学習）

- **背景**：エキスパートの軌道は同じ場面でも複数パターンありうる（マルチモーダル）ため、模倣学習だけだとそれらの「平均」を学んでしまう。たとえば交差点で左に曲がる軌道と右寄りの軌道の中間を通り、衝突や走行可能領域からのはみ出しが起きる（Fig. 4(a)）。
- **基本の考え方**：拡散のノイズ除去過程（x_T → x_{T-1} → … → x_0）を、各ステップで次の状態を選ぶマルコフ決定過程とみなし、GRPOで強化学習する。
- **サンプリング**：同じ入力に対して、ノイズからG本の軌道をそれぞれの拡散チェーンとして生成する（式8）。
- **報酬**：単純なL2距離ではなく、NAVSIMシミュレータで衝突・走行可能領域の順守・快適性を評価したPDMSを報酬にする（シミュレータを報酬に使うのは本論文が初とのこと）。軌道全体を1つの行動とみなし、1ステップの意思決定として扱う。
- **アドバンテージ（式9）**：G本の報酬をグループ内で標準化（平均を引いて標準偏差で割る）し、平均より良い軌道を正、悪い軌道を負とする。
- **確率の計算（式10, 11）**：各ノイズ除去ステップを固定分散のガウス分布とみなすことで、チェーン全体の対数確率を各ステップの対数確率の和として計算できる。
- **損失（式12）**：アドバンテージの高い軌道の確率を上げる強化学習の損失に、探索中にモデルが崩れないよう参照方策を真似る行動クローニングの損失（重みλ）を加える。初期のノイズ除去ステップは不安定なので割引係数γで重みを下げる。
- **簡略化**：PPOのようなクリッピングは省き、更新は1回だけ行う。
- **効果**：模倣を超えて、閉ループ環境で安全かつ快適な軌道を生成できるようになる。

## 番外編：LLMにおける強化学習の必要性

**従来の学習（事前学習＋SFT）**：お手本の文字列をトークン単位で再現する「模倣」の学習。土台作りには有効だが、真似るだけでは超えられない壁がある。

| 従来の問題点 | 強化学習での改善 |
|---|---|
| お手本の質が上限になり、それを超えられない | 報酬を最大化するので、お手本にない良いやり方も見つけられる |
| 正解例しか見ないので「何がダメか」を学ばない | 悪い出力に低い報酬が付き、避けるべき行動も学べる |
| トークン単位の評価で、言い回しの違いも致命的な誤りも同じ重みになる | 「正しいか・役に立つか」で回答全体を評価できる |
| 学習時は正しい文脈、推論時は自分の出力が文脈になるズレがあり、誤りが連鎖する | 自分で生成した出力で学ぶので、ミスからの立て直しも経験できる |
| 良い回答のお手本を大量に人が書くのは高コスト | 「AとBどちらが良いか」の比較や、自動判定できる報酬（数学の正誤、コードのテスト）で学べる |

- **実際の使われ方**：人間の好みで調整するRLHF（対話モデル）と、正解を自動判定できる課題で思考過程を鍛える推論モデル（DeepSeek-R1など）が代表例。
- **注意点**：報酬の抜け穴を突く報酬ハッキングや計算コストの問題があり、強化学習は事前学習→SFTの後に重ねる仕上げの段階として使われる。

| 用語 | 説明 |
|---|---|
| SFT（教師ありファインチューニング） | 質問と模範回答のペアで、模範回答を再現するよう学習すること。 |
| RLHF | 人間の比較データから報酬モデルを作り、強化学習で応答を人間の好みに合わせる手法。 |
| PPO | LLMの強化学習で広く使われてきた手法。価値を見積もる別ネットワーク（クリティック）が必要。 |
| GRPO | 同じ入力に複数の出力を生成し、グループ内の相対評価で更新する手法。クリティック不要で軽い。 |
| 報酬ハッキング | 報酬は高いが中身がおかしい出力を学んでしまう現象。 |
